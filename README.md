# 互相看护（astrbot_plugin_bot_watchdog）

给「另一个 bot」做健康看护的小插件。定时探测对方的健康检查地址，连续失败达到阈值后自动触发对方重启，让两台 bot 互相兜底——一台挂了，另一台把它拉起来。

无指令、无工具，安装并填好配置后自动运行。

## 功能

- **宽容的存活判定**：只要请求能拿到任意 HTTP 响应（包括 401/403）就视为存活，只有连接失败、超时、DNS 解析失败才计为一次失败。这样不会把「服务在跑但要求鉴权」误判成掉线。
- **连续失败才动手**：单次网络抖动不会触发重启，默认连续 3 次失败才判定掉线。
- **两种重启方式**：
  1. 面板接口（优先）：可自动用账号密码登录对方面板拿 Token，再调用重启接口，无需手填长期 Token。
  2. 群指令兜底：没有面板凭据时，退回到在指定会话里发一条重启指令（默认 `-重启`）。
- **冷却保护**：两次自动重启之间有最小间隔（默认 300 秒），避免反复重启。
- **自身重启不丢看护**：插件重新加载后会自动继续看护，不会出现「一边重启完就没人管」的死锁。
- **日志可观测**：每次探测失败、恢复、触发重启都会写日志。

## 安装

把本仓库放到 AstrBot 的 `data/plugins/astrbot_plugin_bot_watchdog/` 目录下，重载插件即可。

也可以在插件市场搜索「互相看护」安装。

## 配置

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `target_name` | string | 目标 bot | 被看护的 bot 名称，仅用于日志和提示 |
| `health_url` | string | 空 | **必填**。被看护 bot 的健康检查地址，例如 `http://127.0.0.1:6185/` |
| `check_interval_seconds` | int | 60 | 检查间隔（秒），最小 10 |
| `failure_threshold` | int | 3 | 连续失败多少次判定为掉线，最小 1 |
| `timeout_seconds` | int | 8 | 单次健康检查超时（秒），最小 3 |
| `panel_base_url` | string | 空 | 对方面板地址，例如 `http://127.0.0.1:6185`；留空则跳过面板方式 |
| `panel_username` | string | 空 | 对方面板登录账号 |
| `panel_password` | string | 空 | 对方面板登录密码 |
| `restart_path` | string | `/api/v1/system/restart` | 对方面板的重启接口路径 |
| `notify_umo` | string | 空 | 兜底时发送重启指令的会话 UMO，例如 `平台ID:GroupMessage:群号` |
| `command_fallback` | string | `-重启` | 兜底发送的指令文本 |
| `restart_cooldown_seconds` | int | 300 | 两次自动重启之间的最小间隔（秒），最小 60 |

`health_url` 留空时插件不会启动看护，只会打一条警告，不会影响 AstrBot 正常运行。

## 工作原理

插件在 `initialize()` 里起一个后台任务，循环执行：等待间隔 → 探测 `health_url` → 成功则清零失败计数，失败则累加并打警告。计数达到 `failure_threshold` 后调用重启流程（面板接口优先，失败则群指令兜底），随后清零计数并进入冷却。

探测放在线程池里跑，不会阻塞事件循环。插件被卸载或 AstrBot 关闭时，任务会被取消。

## 注意事项

- 本插件只能「重启对方」，不能修复对方的具体故障；如果对方是配置写错或依赖缺失，重启可能无效。
- 兜底的群指令方式依赖对方能收到并响应这条指令，请确认指令文本与对方实际指令一致。
- 面板账号密码会以明文存在插件配置里，请自行评估风险；也可以只用兜底方式，不填面板凭据。

## 兼容性

- AstrBot `>= 4.24.4`
- 已在 `aiocqhttp` 平台验证；其它平台理论上可用，但兜底指令需要对方在该平台可接收。
